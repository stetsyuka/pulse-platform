## Фаза 1. Перед стартом задачі (Гігієна середовища і Контексту)

- [ ] Репозиторій розташований на швидкій локальній ФС (`~/Projects/<group>/<repo>` або `~/Work/<repo>` — у нативній Linux ФС для WSL, **поза** Google Drive / Dropbox / iCloud).
- [ ] Актуальний стан синхронізовано з віддаленим сервером (`git fetch && git pull --ff-only`), початковий `git status` перевірено на наявність сторонніх незакомічених файлів.
- [ ] Для паралельної або ризикованої розробки створено ізольоване робоче дерево: `claude -w <feat-or-fix-name>` (перевірено окремий порт для локального стенда та наявність тестового `.env`).
- [ ] Архітектурний план узгоджено в **Plan Mode** (`Shift+Tab`, профіль `opusplan`), побічні дослідження винесено в `/subtask` без засмічення основного вікна.

## Фаза 2. Розробка за Agentic TDD (`Red → Green → Refactor`)

- [ ] **Крок Red:** тести на нову поведінку й крайові випадки написані **до** зміни робочого коду; падіння тестів з очікуваної бізнес-причини перевірено очима.
- [ ] **Крок Green:** реалізація виконана при заблокованому редагуванні папки `tests/`; контрольний `git diff tests/` підтверджує, що існуючі асерти не були ослаблені чи видалені під відповідь.
- [ ] **Крок Refactor:** прибрано дублювання коду, магічні числа та тимчасові налагоджувальні виводи (`/simplify`).

## Фаза 3. Чотиришарова піраміда верифікації (`make check` / `npm run verify`)

- [ ] **Шар 1 — Статична типізація:** `pyright` / `mypy --strict` або `tsc --noEmit` проходить із `0 errors`.
- [ ] **Шар 2 — Швидкий лінтер і форматер:** `ruff check .` або `biome check .` проходить без попереджень.
- [ ] **Шар 3 — Юніт та інтеграційні тести:** `pytest` / `vitest` повністю зелені (включно з інтеграційними тестами БД / API).
- [ ] **Шар 4 — Живий Smoke Test:** локальний сервіс стартує без помилок у логах, `/health` і змінений маршрут відповідають очікуваним статусом і схемою (для UI — перевірено консоль браузера через `claude --chrome`).

## Фаза 5. Чистота Git-історії та закриття задачі

- [ ] **Скан секретів:** у індексі гарантовано відсутні `.env`, `credentials*`, `*.pem`, `*.key`, `client_secret*.json`, хардкод токенів чи внутрішніх IP-адрес.
- [ ] **Поіменний індекс:** використано точковий `git add <files>` (без сліпого `git add .`), перевірено `git diff --staged` — жоден сторонній незакомічений файл не підмішано у коміт.
- [ ] **Чиста історія:** якщо робота велася у карантинній гілці `wip/<task>`, чорнові коміти збереження зібрані через `rebase` / `squash` у логічні атомарні коміти формату **Conventional Commits** (`type(scope): summary` + архітектурне «чому» в описі).
- [ ] **Контурна політика `git push`:**
  - Контур власних проєктів (`~/Projects`): коміт відправлено на сервер для синхронізації робочих машин.
  - Корпоративний контур (`~/Work`): отримано явне підтвердження інженера перед `git push` (щоб контрольовано запустити CI/CD).
- [ ] Оформлено структурований Pull Request (`gh pr create` із описом рішення, звітом перевірок та планом відкату), відпрацьований `worktree` прибрано (`git worktree remove`), фінальний **`git status` чистий**.
