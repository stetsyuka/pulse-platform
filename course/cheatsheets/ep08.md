## 1. Золоте правило Архітектора «CLI First» проти MCP

Перш ніж додавати новий MCP-сервер, перевірте матрицю доцільності *(чим більше схожих інструментів, тим частіше модель вибирає не той)*:

| Задача | Що обрати | Чому |
|---|---|---|
| **Git, GitHub PR/Checks, Docker, K8s, jq** | **Нативний CLI у `Bash`** (`git`, `gh`, `docker`, `kubectl`) | `0` токенів на JSON-схеми при старті, миттєве виконання, моделі Claude 5.5 знають ці утиліти досконало з коробки |
| **Таск-трекери та бази знань** (`Notion`, `Linear`, `Jira`, `Figma`) | **Офіційний MCP** (`Streamable HTTP` або `stdio`) | Немає зручного стандартного CLI; потрібні структуровані операції читання/оновлення карток |
| **Документація бібліотек на льоту** (`Context7`) | **MCP (`@upstash/context7-mcp`)** | Підтягує точні актуальні сигнатури API замість галюцинацій старих версій |
| **Живий браузер, верстка, консоль і мережа** | **`Claude in Chrome` (`claude --chrome`)** | Прямий доступ до DOM, вкладок `Console`/`Network` DevTools та вже авторизованих сесій у вашому браузері |
| **Внутрішній Knowledge Graph / PostgreSQL / Закритий API** | **Власний `FastMCP` або `stdio`-обгортка з `Vault`** | Вузькі типізовані інструменти, `read-only` роль у БД та нуль секретів на диску |

## 2. Транспорти та області видимості (`--scope`)

### Актуальні транспорти:
- **`stdio` (локальний процес):** Claude Code запускає дочірній процес на вашій машині, спілкується через `stdin`/`stdout` (JSON-RPC 2.0) і автоматично передає змінну `CLAUDE_PROJECT_DIR`.
- **`Streamable HTTP` (`--transport http`):** єдиний сучасний стандарт для віддалених хмарних серверів (замінив застарілий подвійний транспорт `SSE`).

### Три області видимості (`--scope`):
1. **`local`** *(за замовчуванням)* — приватне підключення тільки для вас у поточному проєкті (не потрапляє в Git).
2. **`project`** — записується у файл **`.mcp.json`** у корені репозиторію. Комітиться в Git для всієї команди; підтримує безпечне розширення змінних `${VAR:-default}`.
3. **`user`** — глобальне підключення, доступне в усіх ваших проєктах на комп'ютері.

## 3. Бюджет токенів, OAuth по SSH та ключові команди CLI

| Команда / Механізм | Призначення |
|---|---|
| `/context` | Рентген контекстного вікна: показує точну вагу кожного MCP-сервера в токенах та статус відкладених інструментів |
| `/mcp` | Інтерактивна панель у сесії: перевірка статусу, перегляд інструментів `mcp__<сервер>__<дія>`, перезапуск або вимкнення сервера |
| **MCP Tool Search** | Автоматичне відкладене завантаження: замість десятків важких JSON-схем модель тримає легкий індекс і підтягує схему лише в момент виклику (решта схем не займає місця в контексті) |
| `alwaysLoad` | На рівні сервера — поле `alwaysLoad: true/false` у його конфігурації (`false` ховає всі його інструменти за пошуком); на рівні інструмента — метадані `_meta['anthropic/alwaysLoad']` |
| `claude mcp add --transport http --scope project <name> <url>` | Підключення хмарного сервера через `Streamable HTTP` у командний `.mcp.json` |
| `claude mcp add --scope project <name> -- <cmd> [args...]` | Підключення локального `stdio`-сервера (після розділювача `--` йде команда запуску) |
| `claude mcp login <name> --no-browser` | Безпечна авторизація **OAuth 2.1** на віддаленому Linux-сервері по SSH без графічного інтерфейсу (друкує URL для входу з ноутбука чи телефона; адресу, на яку поверне браузер, вставляєте назад у термінал). Сервер із `.mcp.json` спершу має бути схвалений у `claude` або в `enabledMcpjsonServers` |
| `claude --chrome` (або `/chrome`) | **Claude in Chrome**: робота з живими вкладками, перевірка верстки, читання помилок `Console` та `Network` |

## 4. Три закони написання власного сервера на Python (`FastMCP`)

1. **Контракт Pydantic та docstring — це 50% успіху:** модель не бачить тіла функції — вона читає лише назву, опис у `@mcp.tool(description=...)` та підказки `Field(..., description=..., ge=1, le=15)`.
2. **Компактний структурований текст замість сирого JSON:** ніколи не повертайте дампи з БД на тисячі рядків. Відфільтруйте дані на боці Python і поверніть лаконічний Markdown-список на 10–20 рядків.
3. **Стерильний `stdout` (логер суворо у `sys.stderr`):** у `stdio`-серверах потік `stdout` використовується виключно для повідомлень JSON-RPC. Один випадковий `print()` або `console.log()` у `stdout` миттєво ламає протокол!

## 5. Патерн «Нуль секретів на диску» (`HashiCorp Vault` + `PostgreSQL`)

Чотири обов'язкові інженерні правила для скрипта-обгортки [`vault-postgres-mcp-wrapper.example.sh`](https://github.com/stetsyuka/pulse-platform/blob/main/course/starter-kit/ep08/vault-postgres-mcp-wrapper.example.sh):

- [ ] **Жодних паролів у `.mcp.json`:** у конфігурації зберігається лише шлях до скрипта та несекретний шлях `secret/demo-app/database`.
- [ ] **Логи виключно у `stderr` (`>&2`):** функція `log()` пише тільки у потік помилок, залишаючи `stdout` чистим для MCP.
- [ ] **Захист вхідного потоку `stdin` (`</dev/null` або `ssh -n`):** дочірні виклики `vault` чи `ssh` не повинні «проковтнути» стартові JSON-RPC байти від Claude Code.
- [ ] **Заміщення процесу через `exec` + режим `--test`:** фінальний рядок `exec uv run --python 3.12 --with "mcp==1.30.0" python mcp-knowledge-server.example.py` (DSN — у змінній `DATABASE_URL`) передає керування й сигнали `SIGTERM` напряму серверу без зайвого процесу bash; `--test` перевіряє Vault і друкує лише довжину секрету.

## 6. Чекліст безпеки MCP у 2026 році

- **Захист від *MCP Tool Poisoning*:** не підключайте неперевірені сервери з відкритих агрегаторів; тримайте активними правила `deny` на `~/.ssh`, `~/.aws`, `.env` (Серія 03) та детерміновані `PreToolUse`-хуки (Серія 06).
- **Захист від *Rug-Pull* підміни пакетів:** **ніколи не пишіть `@latest`** у `.mcp.json` (`npx -y @unknown/pkg@latest`). Завжди фіксуйте точні перевірені версії пакетів (`@upstash/context7-mcp@4.6.0`, `mcp==1.30.0`). Архівовані пакети (як `@modelcontextprotocol/server-postgres`) не використовуйте взагалі.
- **Принцип найменших привілеїв у БД:** підключайте аналітичний MCP-сервер виключно під роллю `READ ONLY` (`GRANT SELECT`) на репліці (`db-readonly.internal.example`) із примусовим обмеженням `statement_timeout = '5s'`.

## 7. Практичне завдання до Серії 08

- 🟢 **Базовий рівень:** Підключіть у свій проєкт сервер документації `Context7` із чітко зафіксованою версією (`@upstash/context7-mcp@4.6.0`, потрібен Node 20+), перевірте його вагу в токенах через `/context` та статус у `/mcp`, а потім запустіть `claude --chrome` і попросіть агента проінспектувати верстку й консоль вашого локального фронтенду.
- 🟡 **Поглиблений рівень:** Запустіть власний сервер на базі шаблону [`mcp-knowledge-server.example.py`](https://github.com/stetsyuka/pulse-platform/blob/main/course/starter-kit/ep08/mcp-knowledge-server.example.py), додайте 2 типізовані інструменти з `Pydantic Field` під ваш проєкт, переконайтеся, що всі логи йдуть у `stderr`, і пропишіть дозвіл `mcp__arch-kg__*` у `.claude/settings.json`.
- 🔴 **Архітектурний рівень:** Повністю приберіть відкриті паролі та токени зі своїх конфігів MCP на диску — налаштуйте динамічну обгортку через **HashiCorp Vault** (або системний Keychain ОС) за шаблоном [`vault-postgres-mcp-wrapper.example.sh`](https://github.com/stetsyuka/pulse-platform/blob/main/course/starter-kit/ep08/vault-postgres-mcp-wrapper.example.sh) із перевіркою `--test`, системним викликом `exec` та окремою `read-only` роллю в PostgreSQL із `statement_timeout = '5s'`.
