## 1. Головні події хуків (`v2.1.322`: понад 30 подій, тут — ті, що потрібні щодня)

| Фаза | Подія | Коли спрацьовує | Чи може блокувати (`exit 2` / JSON)? | Типове інженерне застосування |
|---|---|---|---|---|
| **1. Вхід і запит** | **`SessionStart`** | Старт, `--resume`, `/clear`, `/compact` або `fork` | Ні (впорскує контекст) | `git-sync-start.sh`: безпечний `fetch` + `--ff-only` і статус репо в контекст |
| | **`UserPromptSubmit`** | Користувач натиснув `Enter` | Так / додає контекст | Автоматичне додавання активної гілки чи ID задачі до запиту |
| **2. Ворота дій і дозволів** | **`PreToolUse`** | Перед викликом будь-якого інструмента | **Так (`exit 2` / `deny` / `updatedInput`)** | Блокування `.env`, `DROP TABLE`, `rm -rf`, підстановка `--dry-run=client` |
| | **`PermissionRequest`** | Перед показом діалогу дозволу людині | **Так (`allow` / `deny`)** | Автосхвалення безпечних тестів або розумний звуковий сигнал людині |
| | **`PermissionDenied`** | Коли класифікатор **Auto Mode** відхилив дію | Ні (post-facto; підтримує `retry: true`) | Логування відмов класифікатора та підказка безпечної альтернативи для повтору |
| **3. Після виконання** | **`PostToolUse`** | Одразу після успішного виконання інструмента | Ні (зворотний зв'язок) | Автоформатування за 50 мс (`ruff format`, `biome check --write`), аудит команд |
| | **`PostToolUseFailure`** | Коли інструмент упав із помилкою | Ні (додає контекст) | Автоматична підказка типовій помилці збірки чи підключення до тестової БД |
| **4. Моделі, рої та дерева** | **`PreModelSwitch`** | Перед перемиканням моделі (`/model` або SDK) | **Так** (заблокувати, підтвердити або доповнити) | Контроль бюджету та заборона переходу на несанкціонований тарифний рівень |
| | **`PostModelSwitch`** | Після зміни моделі або fallback-переходу | Ні | Логування зміни моделі та коригування системних підказок |
| | **`SubagentStart`** | При старті субагента (`Agent` tool) | Ні | Ініціалізація телеметрії та трасування рою субагентів |
| | **`SubagentStop`** | Коли субагент завершує роботу | **Так (`exit 2`)** | Перевірка, чи субагент виконав контракт перед поверненням звіту |
| | **`WorktreeCreate`** | Створення нового дерева (`claude -w`) | Ні | Автокопіювання `.env.test` або локальних фікстур у новий worktree |
| | **`WorktreeRemove`** | Видалення робочого дерева | Ні | Очищення тимчасових контейнерів або тестових схем БД |
| | **`ConfigChange`** | Зміна файлів налаштувань посеред сесії | **Так (`exit 2`)** | Захист від несанкціонованої модифікації конфігів під час роботи |
| **5. Стиснення і вихід** | **`PreCompact`** | За секунду до стиснення контексту (`/compact`) | Ні | Збереження критичних проміжних даних у файл перед компактифікацією |
| | **`Notification`** | Системні сповіщення очікування клієнта | Ні | Інтеграція зі зовнішніми панелями статусу |
| | **`Stop`** | Коли головний агент завершив відповідь | **Так** (перевіряйте `stop_hook_active`!) | `git-sync-stop.sh` (нагадування про незакомічене), десктоп/Telegram-сповіщення |
| | **`SessionEnd`** | Повне закриття сесії Claude Code | Ні | Закриття фонових тунелів і прибирання `/tmp` |

Інші події (`FileChanged`, `CwdChanged`, `InstructionsLoaded`, `PostCompact`, `StopFailure`, `TaskCreated`/`TaskCompleted`, `Elicitation` та ін.) — у документації Claude Code; повний перелік активних хуків показує `/hooks`.

## 2. Протокол кодів повернення та JSON-рішень

**`exit 0` (Дозвіл / Ін'єкція контексту):**

- Для `SessionStart` та `UserPromptSubmit`: будь-який текст із `stdout` додається прямо в контекст сесії.
- Для керування рішеннями: поверніть у `stdout` структурований JSON:

```json
{
  "systemMessage": "🛡 Хук безпеки додав --dry-run=client до kubectl apply",
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "permissionDecisionReason": "kubectl apply переведено в --dry-run=client.",
    "updatedInput": {
      "command": "kubectl apply --dry-run=client -f k8s/deployment.yaml"
    }
  }
}
```

**`exit 2` (Залізобетонне блокування + Самовиправлення агента):**

- Дія миттєво скасовується.
- Увесь текст із потоку помилок **`stderr` (`>&2`)** передається прямо моделі як офіційна причина відмови. Пишіть у `stderr` конструктивну інструкцію (наприклад: *«Читання `.env` заборонено. Прочитай структуру змінних у `.env.example`»*) — тоді агент виправиться сам.

**`exit 1` (та інші коди, крім `0` і `2`):**

- **НЕ блокує виконання!** Вважається нефатальним збоєм самого хука (видно в журналі відладки, але дія виконується). Ніколи не використовуйте `exit 1` для блокування!

## 3. Матчери, умова `if`, async і типи обробників

- **Чутливість до регістру:** `"Bash"`, `"Read|Edit|Write"`, `"mcp__postgres__.*"` (написання `"bash"` з малої літери **не спрацює**!).
- **Декларативна умова `"if"` всередині хука:** фільтрує виклик за синтаксисом правил дозволів ще **до створення дочірнього процесу ОС**:

```json
{
  "matcher": "Bash",
  "hooks": [
    {
      "type": "command",
      "if": "Bash(git commit*)",
      "command": "cd \"$CLAUDE_PROJECT_DIR\" && uv run pytest -q --tb=short >&2 || exit 2",
      "timeout": 120
    }
  ]
}
```

- **Асинхронні хуки:** додайте `"async": true` для логування, телеметрії та звукових сигналів, щоб агент не чекав завершення процесу.
- **Таймаут:** за замовчуванням Claude Code чекає на хук до 10 хвилин — ставте свій `"timeout"` у 10–30 с.
- **`allow` лише для простої команди:** якщо `PreToolUse` повертає `allow` разом з `updatedInput`, перевірте, що в команді немає ланцюжків (`&&`, `;`, `|`), інакше поверніть `ask`.
- **5 типів обробників (`type`):**
    - `"command"` — локальний скрипт (мілісекунди, \$0, детермінізм — **основний вибір Архітектора**).
    - `"http"` — відправка JSON-події `POST`-запитом на вебхук.
    - `"mcp_tool"` — виклик інструмента підключеного MCP-сервера.
    - `"prompt"` — швидка оцінка умови легкою LLM-моделлю (для змістовних критеріїв, які не описуються regex).
    - `"agent"` — запуск ізольованого субагента-верифікатора з доступом до файлів.

## 4. Безпека та швидка відладка

1. **Чужий `.claude/settings.json` = потенційний RCE:** хуки в клонованому репозиторії виконують довільний шелл-код від вашого імені. Завжди перевіряйте `.claude/settings.json` та папку `.claude/hooks/` очима перед підтвердженням довіри у новому проєкті!
2. **Абсолютні шляхи та права виконання:** завжди видавайте `chmod +x` скриптам і вказуйте шляхи через `"$CLAUDE_PROJECT_DIR/.claude/hooks/..."` або `"$HOME/.claude/hooks/..."` (під час роботи поточна папка `cwd` може змінюватися).
3. **Захист від зациклення `Stop`-хуків:** перевіряйте `stop_hook_active`. Нотифікатор при `true` одразу виходить; блокувальний хук (як `stop-make-check.sh`) рахує спроби й після трьох здається.
4. **Діагностика за хвилину:**

    - Ручний прогін без агента: `echo '{"tool_name":"Read","tool_input":{"file_path":".env"}}' | python3 .claude/hooks/guard-destructive-commands.py ; echo $?`
    - Повна хроніка викликів, таймінгів і кодів повернення: **`claude --debug=hooks`** (або `--debug-file <шлях>`), посеред сесії — **`/debug`**. Огляд усіх хуків і їхніх джерел — **`/hooks`** (лише перегляд: змінюють їх у settings.json). Запуск без хуків і плагінів — **`claude --bare`**.

## 5. Практичне завдання до Серії 06 (три рівні)

- 🟢 **Базовий рівень:** Скопіюйте зі `starter-kit/ep06/` конфігурацію `PostToolUse` для автоформатування (`ruff format` для Python або `biome check --write` для TypeScript) та базовий `PreToolUse`-захист на читання `.env` із кодом `exit 2`. Попросіть агента прочитати `.env` у тестовому проєкті й переконайтеся через `/debug`, що хук заблокував дію, а агент самостійно переключився на `.env.example`.
- 🟡 **Поглиблений рівень:** Встановіть у `~/.claude/hooks/` глобальну пару скриптів `git-sync-start.example.sh` та `git-sync-stop.example.sh` для своїх робочих контурів `~/Projects` та `~/Work`. Додайте у проєктний `.claude/settings.json` хук із декларативною умовою `"if": "Bash(git commit*)"`, який блокує коміт при червоному `pytest`, та підключіть розумний нотифікатор `smart-notify.example.py` (чотири сита: `stop_hook_active`, `agent_id`, поріг тривалості, фокус вікна).
- 🔴 **Архітектурний рівень:** Розгорніть у своєму основному репозиторії повний Python-щит `guard-destructive-commands.example.py` із трьома рівнями захисту: блокування читання секретів як через `Read`, так і через `Bash` (`cat`/`grep`), блокування руйнівних команд БД та інфраструктури (`DROP TABLE`, `alembic downgrade base`, `terraform destroy`, `git push --force origin main`) та прозору модифікацію аргументів на льоту через `updatedInput` (автоматичне додавання `--dry-run=client` до `kubectl apply`). На `Stop` поставте `stop-make-check.example.sh`, щоб агент не завершував роботу з червоним `make check`.
