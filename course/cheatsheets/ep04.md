# Шпаргалка до Серії 04: Формула ідеальної задачі, Plan Mode, сесії та `opusplan` (Листопад 2026)

> Матеріал до 4-ї серії курсу **«Архітектор проєктів з Claude Code»** (`InferenceLab`, актуально для `v2.1.318+`).

## 1. Формула 4К Архітектора (анатомія ТЗ для термінала)

1. **Контекст і Ціль:** конкретний інженерний результат без води (*«Додай асинхронну відправку вебхуків зі статусом замовлення, підписом `HMAC-SHA256` і 3 ретраями»*).
2. **Координати входу + Зразок (`@`):** точні файли старту та еталон стилю (*«Подивись `@src/notifications/email_worker.py` і побудуй за тим самим патерном»*).
3. **Кордони («Чого НЕ чіпати»):** явні заборони (*«Не змінюй публічний контракт `@src/api/v1/orders.py`, не додавай нових пакетів у `pyproject.toml`, не редагуй старі міграції»*).
4. **Критерій приймання (Definition of Done):** детермінована команда перевірки (*«`pytest tests/webhooks/` зелений, `mypy src/` — 0 помилок»*).

**Додаткові канали входу:**
- **Візуальний референс:** вставка скріншота помилки, схеми чи макета Figma прямо у термінал (`Ctrl + V` або перетягування файлу).
- **Unix-пайп для сирих трейсів:** `tail -n 120 logs/error.log | claude -p "Знайди першопричину, вкажи файл і рядок"`.

## 2. Золотий цикл та робота в `Plan Mode`

`Explore (Розвідка)` → `Plan (Проєктування й компроміси)` → `Execute (Код за планом)` → `Verify (Тести й типи)`

- **Вхід у `Plan Mode`:** `Shift + Tab` посеред сесії, команда `/plan` (CLI та VS Code) або старт `claude --permission-mode plan`.
- **Прийом «Архітектурна рада»:** перед вибором реалізації попросіть запропонувати **2–3 архітектурні підходи** з плюсами, мінусами та ризиками, а обраний варіант зафіксуйте коротким ADR у `docs/decisions/NNN-topic.md`.
- **Хірургічна правка плану (`Ctrl + G`):** замість суперечок у чаті натисніть `Ctrl + G`, відредагуйте згенерований план прямо у своєму `$EDITOR` (VS Code / Cursor / Neovim), збережіть — і агент виконає саме вашу версію.

## 3. Маршрутизація інтелекту та бюджету (`v2.1.318`)

| Інструмент / Режим | Призначення |
|---|---|
| **`/model opusplan`** *(головна зброя)* | У `Plan Mode` працює **Opus 5.5** (`\$4/\$20`) для глибокого креслення; на фазі виконання автоматично вмикається швидкий **Sonnet 5.5** (`\$2/\$10`) |
| **`/effort low`** | Швидкі механічні правки конфігів, перейменування, прості тести |
| **`/effort medium`** | Збалансований дефолт для **Opus 5.5** у повсякденній роботі |
| **`/effort high`** | Багатофайлові фічі, інтеграції сервісів, міграції БД |
| **`/effort xhigh` / `max`** | Пошук race conditions, витоків пам'яті, проєктування складного ядра (для екстремальних вузлів — `/model fable`) |
| **`/fast`** *(на Opus 5.5)* | Прискорення видачі у `2.5×` за `2×` тарифу під час термінового дебагу інцидентів (вимкніть повторним `/fast` після фіксу) |

> **Застаріло у другій половині 2026:** хмарний `/ultraplan` видалено (`v2.1.222`); службові списки `TodoWrite`/`TaskCreate` приховано на моделях покоління Claude 5/5.5 (`v2.1.233`) — для автономної роботи до критерію використовуйте плани у файлах та `/goal`.

## 4. Гігієна сесій та розгалуження: `/subtask` проти `/fork`

- **Правило чистоти:** *Одна логічна задача — одна чиста сесія* (`/clear` після коміту фічі).
- **Зміна директорії без втрати кешу:** `/cd шлях/до/сервісу`.
- **Каталог сесій:** `/rename <осмислена-назва>` на старті → миттєвий пошук у `claude --resume` (або `claude --continue` після обриву термінала).

| Команда (`v2.1.212+`) | Де працює | Коли використовувати |
|---|---|---|
| **`/subtask <запит>`** | Субагент **з копією вашого контексту**; його розвідка не потрапляє в головну розмову | Перевірити ризиковану технічну гіпотезу чи розвідати 15 файлів без засмічення головного контексту (повертає лише стислий висновок) |
| **`/fork`** | Окрема **фонова сесія-клон** (значок `⑂` у `--resume`, окремий рядок у `claude agents`) | Відбрунькувати знайдений побічний баг або паралельно протестувати альтернативну архітектуру у фоні, не зупиняючи основну роботу |

## 5. Багатоденні задачі та багатофайлова хірургія (10–30 файлів)

- **Естафета `HANDOFF.md`:** наприкінці дня попросіть агента записати у `HANDOFF.md`: *1) Що зроблено і протестовано; 2) Точка зупинки; 3) Виявлені граблі/рішення; 4) Точні 3 кроки на старт завтра*. Вранці нова чиста сесія стартує за 10 секунд!
- **Карантинні гілки:** ведіть багатосесійну роботу в `wip/<task>` із атомарними комітами після кожного зеленого кроку.
- **Фокусний `/compact`:** не чекайте сліпого `--autocompact` — стискайте вручну зі збереженням суті: `/compact Збережи схему таблиці X, змінені файли та помилку в pytest; старі логи пошуку відкинь`.
- **Порядок `Contract-First` (знизу вгору з перевіркою на кожному шарі):**
  1. Схеми БД, міграції та типи (`Pydantic` / `Zod` / `TypeScript`) → перевірка типів.
  2. Чисте ядро бізнес-логіки → юніт-тести.
  3. Адаптери, воркери черги та HTTP-роутери → інтеграційні тести.
  4. Фронтенд-клієнт та документація.
- **Масова заміна по репо:** `1. Grep (без правок, виключивши .venv / node_modules / старі міграції)` → `2. Таблиця збігів на екран` → `3. Апрув людини` → `4. Заміна + компілятор і тести`.

## 6. Senior Spec-Driven цикл (`superpowers`-підхід)

1. **Інтерактивне інтерв'ю:** у `Plan Mode` на Opus 5.5 попросіть *НЕ писати код чи план*, а спочатку поставити **5 найгостріших питань** про граничні випадки, безпеку, ідемпотентність та збої.
2. **Генерація Design Spec:** збережіть узгоджену специфікацію у `docs/specs/YYYY-MM-feature-design.md` із розбиттям на атомарні чекпойнти.
3. **Незалежне рев'ю спеки:** перевірте документ у свіжій сесії очима критика, закомітьте в Git і виконуйте по чекпойнтах.

## 7. Практичне завдання до Серії 04

- 🟢 **Базовий рівень:** Увімкніть `/model opusplan` і перемкніться у `Plan Mode` (`Shift+Tab`). Опишіть реальну задачу зі свого проєкту за формулою 4К (використавши шаблон `ep04/TASK-BRIEF-TEMPLATE.md` і `@`-посилання), відредагуйте згенерований план у своєму редакторі через `Ctrl+G` і доведіть реалізацію до зеленого автотесту.
- 🟡 **Поглиблений рівень:** Назвіть робочу сесію через `/rename`. На етапі проектування запустіть `/subtask`, щоб перевірити вузьке місце бібліотеки чи конфігурації без засмічення основної розмови. Потім відбрунькуйте побічну ідею у фонову сесію через `/fork` і знайдіть її через `claude --resume`.
- 🔴 **Архітектурний рівень:** Реалізуйте модуль на 5+ файлів за повним Spec-Driven процесом: проведіть інтерв'ю на 5 гострих питань із Opus 5.5, зафіксуйте дизайн-спек у `docs/specs/`, виконайте перші 2 чекпойнти у гілці `wip/` за порядком `Contract-First`, згенеруйте `HANDOFF.md` і завершіть фінальні чекпойнти у новій чистій сесії.
