## 1. Три стовпи майстерності Архітектора

| Стовп | Суть | Головні інструменти у Claude Code |
|---|---|---|
| **1. Контекст** | Що агент знає і бачить просто зараз (без інформаційного сміття та *Context Rot*) | `CLAUDE.md`, `AGENTS.md`, `.claude/rules/`, `@файл`, `/memory`, `/compact`, `/clear` |
| **2. Декомпозиція** | Розбиття задачі на атомарні кроки за циклом «План → Код → Перевірка» | `Plan Mode` (`Shift+Tab`), `opusplan`, `/effort`, `/subtask`, `/fork`, субагенти |
| **3. Верифікація** | Детермінована перевірка замість сліпої довіри словам моделі | Автотести (`!pytest` / `!npm test`), `Hooks` (`exit 2`), `Sandbox`, `/code-review ultra`, `Esc+Esc` (`/rewind`) |

## 2. Шість механізмів платформи Claude Code

1. **`CLAUDE.md` / `AGENTS.md` / `.claude/rules/`** — паспорт проєкту, архітектурні конвенції та правила для конкретних папок.
2. **`Skills` (`.claude/skills/`)** — багаторазові алгоритми під типові задачі (завантажуються в контекст ліниво за потреби).
3. **`Hooks`** — шелл-скрипти життєвого циклу, які гарантовано спрацьовують детерміновано (навіть якщо LLM забула інструкцію).
4. **`MCP Servers`** — підключення до зовнішніх баз даних, трекерів задач (Notion, GitHub, Linear) та браузера (`Claude in Chrome`).
5. **`Plugins`** — готові версіоновані пакети розширень із маркетплейсів.
6. **`Claude Mods` *(новинка осені 2026)*** — JS/TS-модифікації клієнта, власні статус-панелі (`context-bar`) та програмні перехоплювачі перевірок інструментів.

## 3. Лінійка моделей Claude 5.5 + Fable 5.1 та економіка (Листопад 2026)

Усі актуальні моделі підтримують **нативний контекст 1 000 000 токенів**. Модель за замовчуванням залежить від тарифу й способу входу — поточну показує `/model`.

| Модель (`/model`) | Вхід / Вихід за 1M токенів | Роль у команді Архітектора |
|---|---|---|
| **Haiku 5.5** | `\$0.10` / `\$0.50` | Швидкий пошук, перейменування, дрібна рутина, рій легких субагентів |
| **Sonnet 5.5** | `\$2.00` / `\$10.00` | Головна робоча конячка для більшості щоденної розробки, тестів і багфіксів |
| **Opus 5.5** | `\$4.00` / `\$20.00` | Системний архітектор: складне планування, багатофайлові рефакторинги, глибоке рев'ю |
| **Fable 5.1** (`fable`) | `\$10.00` / `\$50.00` | Спеціалізований скальпель для надскладних алгоритмічних та дослідницьких задач |
| **`opusplan`** *(гібрид)* | Комбіновано | Opus 5.5 будує архітектурний план → Sonnet 5.5 швидко та економно пише код |

**Тарифи підписки проти API:**
- **Pro (`\$20/міс`)** — старт, навчання, невеликі проєкти.
- **Max (`\$100/міс`)** — 5× ліміту Pro для щоденної інженерної роботи.
- **Ultra (`\$200/міс`)** — 10× тижневого ліміту без жорсткої 5-годинної стелі (для верифікованих акаунтів).
- **API (Pay-as-you-go)** — для нерегулярного використання або автоматизованих серверних / CI/CD пайплайнів.

## 4. Чекліст інженерної гігієни середовища

- [ ] **Нативний автооновлюваний інсталятор** (замість застарілого `npm install -g`):
  - macOS / Linux / WSL: `curl -fsSL https://claude.ai/install.sh | bash`
  - Windows PowerShell: `irm https://claude.ai/install.ps1 | iex`
- [ ] **Для користувачів Windows + WSL2:** код лежить **виключно всередині Linux FS** (`~/Projects/...`), а НЕ на `/mnt/c` чи `/mnt/d` (різниця швидкості `git status` становить `0.07s` проти `3.9s` — у **54 рази**!). Редактор відкриваємо через `Remote-WSL`.
- [ ] **Жодних хмарних папок синхронізації:** робочі Git-репозиторії ніколи не лежать у Google Drive, Dropbox або iCloud.
- [ ] **Фізичне розділення контурів:** особисті проєкти в `~/Projects/`, робота на замовника/роботодавця — у `~/Work/` з автопідстановкою пошти через `includeIf` у `~/.gitconfig`.
- [ ] **Перевірка здоров'я:** `claude doctor` показує зелені галочки без помилок конфігурації.

## 5. П'ять рівнів пріоритету налаштувань (`settings.json`)

Від найвищого до найнижчого *(заборони з усіх рівнів завжди додаються!)*:
1. **Managed settings** (корпоративна політика безпеки компанії).
2. **Прапорці CLI** поточного запуску (`--permission-mode plan`, `--worktree` тощо).
3. **`.claude/settings.local.json`** (особисті налаштування конкретного репо, у `.gitignore`).
4. **`.claude/settings.json`** (спільні командні налаштування проєкту в Git).
5. **`~/.claude/settings.json`** (ваші глобальні користувацькі налаштування).

## 6. Гарячі клавіші та префікси першої необхідності

| Комбінація / Команда | Дія |
|---|---|
| `@шлях/до/файлу` | Точне наведення агента на файл із миттєвим автодоповненням |
| `!команда` | Пряме виконання bash-команди (наприклад, `!git status`) без витрати ходу LLM |
| `Shift + Tab` | Перемикання режимів по колу: `auto mode` → `accept edits` → `plan mode` |
| `Esc` × 2 (або `/rewind`) | Машина часу: відкат діалогу та/або змін у файлах до попереднього кроку |
| `Alt + P` (або `/model`) | Перемикання моделі прямо посеред сесії |
| `Alt + T` | Увімкнення / вимкнення режиму розширеного міркування |
| `/compact [фокус]` | Кероване стиснення історії зі збереженням вказаного фокусу |
| `/memory` | Перегляд та редагування нотаток `Auto-memory` проєкту |
| `/doctor` | Повна самодіагностика клієнта та конфігурації |
| `Ctrl + D` → `claude -c` | Вихід із сесії та миттєве продовження останньої розмови (`--continue`) |

## 7. Практичне завдання до Серії 01

- 🟢 **Базовий рівень:** Встановіть Claude Code через нативний інсталятор і запустіть `claude doctor`. Відкрийте будь-який власний репозиторій, перемкніться у **Plan Mode** (`Shift+Tab`), вкажіть ключовий файл через `@` і попросіть агента скласти карту модуля та знайти 3 потенційні вразливості чи вузькі місця.
- 🟡 **Поглиблений рівень:** Заміряйте `time git status` у своєму робочому репо (на Windows перенесіть проєкт із `/mnt/*` у нативний `~/Projects` у WSL і порівняйте час). Створіть глобальний `~/.claude/settings.json` та локальний `.claude/settings.local.json` і перевірте їхню валідність через `claude doctor`.
- 🔴 **Архітектурний рівень:** Налаштуйте фізичне розділення `~/Projects/` та `~/Work/` через директиву `includeIf` у `~/.gitconfig`. Складіть таблицю з 6 пунктів для свого головного проєкту: які правила підуть у `CLAUDE.md`, які рутинні операції стануть `Skills`, які заборони треба закрити детермінованими `Hooks`, а які зовнішні джерела підключити через `MCP`.
