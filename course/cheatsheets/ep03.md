## 1. Чотири інтерактивні режими роботи (`Shift + Tab`) та службові режими

| Режим | Значення у CLI / JSON | Як працює | Коли вмикати |
|---|---|---|---|
| **`Auto Mode`** *(дефолт із `v2.1.283`)* | `auto` | Друга модель-класифікатор мовчки пропускає безпечну рутину (тести, лінтер, правки коду) і зупиняє ризиковані дії | **основний режим щоденної розробки** замість застарілого `--dangerously-skip-permissions` |
| **`Plan Mode`** | `plan` | Стерильний режим архітектора: читання коду та перевірені оглядові команди без жодного запису на диск | Проєктування фіч, аудит коду, перше знайомство з репозиторієм |
| **`Accept Edits`** | `acceptEdits` | Автоматично приймає правки файлів у проєкті, але питає підтвердження перед кожним запуском `Bash` | Коли довіряєте змінам коду, але контролюєте кожну команду шеллу вручну |
| **`Manual`** *(колишній `default` до `v2.1.200`)* | `manual` *(або `default`)* | Запитує підтвердження і на редагування файлів, і на команди термінала, і на мережу | Покрокова хірургія критичного легасі-вузла |
| **Headless без вікон** | `--permission-prompts none` | Усе, що не дозволено явно і потребує діалогу, миттєво відхиляється без зависання процесу | Фонові серверні скрипти та автоматизовані конвеєри (`v2.1.259+`) |
| **Чистий старт без хуків репо** | `--bare` | Пропускає хуки, плагіни, автопам'ять і автозавантаження `CLAUDE.md`. **Працює лише з `ANTHROPIC_API_KEY`** — на підписці Pro/Max не автентифікується | Безпечний перший огляд чужого клонованого репозиторію |

> **Табу Архітектора:** прапорець `--dangerously-skip-permissions` (`bypassPermissions`) допустимий **виключно** в одноразових ізольованих контейнерах без мережі та секретів. У командному `.claude/settings.json` його блокують параметром `"disableBypassPermissionsMode": "disable"`.

## 2. Класифікатор безпеки Auto Mode та команди керування

- **Зелений коридор (без запитань):** читання й редагування файлів проєкту, локальні тести (`pytest`, `vitest`, `cargo test`), лінтери (`ruff`, `biome`), локальні операції `git status`, `git diff`, `git log`, `git commit`.
- **Червоні стоп-тригери (запит людині):**
  1. **Ексфільтрація в мережу:** `curl -X POST`, `wget`, `ssh`, передача даних на невідомі зовнішні хости.
  2. **`Containment Escape` (`v2.1.257+`):** видалення, переміщення або зміна файлів за межами робочої папки проєкту.
  3. **Спільна та прод-інфраструктура:** `git push --force`, `npm publish`, `kubectl delete`, `terraform apply/destroy`, скидання зовнішніх БД.
  4. **Ескалація привілеїв:** `sudo`, зміна системних файлів, SSH-ключів або самих налаштувань безпеки.
- **Команди налаштування:**
  - `/auto-mode-setup` *(новинка `v2.1.304`)* — покроковий майстер: читає проєкт і недавні сесії та налаштовує auto mode під ваші внутрішні домени й тестові стенди. Вмикається для акаунтів поступово: якщо бачите `Unknown command`, те саме видно й редагується через `claude auto-mode config` та вкладку **Auto mode** у `/permissions` (Soft allow / Soft deny / Hard deny / Environment).
  - `/permissions` — перегляд усіх активних правил та вкладки Auto Mode.
  - `claude auto-mode reset` — повернення налаштувань auto mode до стандартних.

## 3. Конвеєр правил `settings.json` та синтаксис масок

**Порядок перевірки (завжди незмінний):**
`1. deny (блок за 1 мс)` → `2. allow (пропуск)` → `3. ask (питання людині)` → `4. Активний режим (Auto Mode)`

*Заборони `deny` з усіх 5 рівнів конфігурації завжди складаються — скасувати глобальний чи корпоративний `deny` локальним файлом неможливо.*

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "defaultMode": "auto",
    "disableBypassPermissionsMode": "disable",
    "blockReadsOutsideWorkingDirectories": true,
    "blockWritesOutsideWorkingDirectories": true,
    "allow": [
      "Bash(pytest:*)",
      "Bash(ruff check:*)",
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git commit:*)"
    ],
    "ask": [
      "Bash(git push:*)",
      "Bash(terraform apply:*)",
      "Edit(infra/prod/**)"
    ],
    "deny": [
      "Read(.env)",
      "Read(.env.*)",
      "Read(**/.env*)",
      "Read(**/*.pem)",
      "Read(**/*.key)",
      "Read(**/credentials*)",
      "Bash(sudo:*)",
      "Bash(rm -rf /:*)",
      "Bash(git push --force:*)"
    ]
  }
}
```

- **`blockReadsOutsideWorkingDirectories: true`** (`v2.1.257`) — фізично забороняє читати файли поза робочою директорією.
- **`blockWritesOutsideWorkingDirectories: true`** (`v2.1.314`) — фізично забороняє записувати або змінювати файли поза робочою директорією.
- **Антипатерн:** ніколи не пишіть `"Bash(*)"` у `allow` і ніколи не ставте `"*"` у мережеві домени пісочниці.

## 4. Нативна пісочниця ядра ОС (`/sandbox`)

Навіть якщо `Bash(pytest:*)` дозволено, скомпрометований пакет у `node_modules` чи `.venv` може породити підпроцес. **Sandbox** ізолює всю групу процесів на рівні ядра ОС без важкого Docker:
- **macOS:** системний механізм **Apple Seatbelt**.
- **Linux та Windows WSL2:** **bubblewrap (`bwrap`)** + Linux namespaces.
- **Файловий купол:** запис дозволено тільки в поточну папку проєкту та `/tmp`. Доступ до `~/.ssh`, `~/.aws`, `~/.kube`, `/etc` блокується ядром (`Operation not permitted`).
- **Linux:** шар пісочниці ігнорує glob-маски (`**/.env`) у правилах `Read`/`Edit` — для нього вказуйте конкретні шляхи; `claude doctor` про це попереджає. Правила для самих інструментів Read/Edit маски розуміють.
- **Мережевий купол (`sandbox.network.allowedDomains`):** весь зовнішній трафік закритий за замовчуванням, окрім білого списку доменів (`github.com`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`).
- **Перевірка:** `/sandbox` у сесії або `claude doctor` у терміналі.

## 5. Уроки зламів 2026 та протокол огляду чужого коду

1. **`CVE-2026-21852` (`ANTHROPIC_BASE_URL`):** шкідливий клонований репозиторій підкладав у `.claude/settings.json` адресу фальшивого API-сервера для перехоплення ключів ще до вікна довіри. Вразливість закрита патчем, але **вікно довіри до нової папки ніколи не можна проклікувати не дивлячись**.
2. **Непрямий Prompt Injection:** приховані інструкції в чужих PR, текстах Issue або на вебсторінках (`WebFetch`). Зупиняються лише технічною зв'язкою `deny` на секрети + мережевий фільтр `/sandbox`.
3. **Протокол для будь-якого чужого репозиторію з інтернету:**
   - Крок 1: перевірити очима `ls -la .claude .mcp.json`.
   - Крок 2: перший запуск — `claude --permission-mode plan`, довіру до папки не підтверджувати до перегляду налаштувань (з ключем API — додатково `--bare`).
   - Крок 3: для справді незнайомого коду — окремий контейнер або VM.

## 6. Гігієна секретів та асиметричний контур `~/Projects` проти `~/Work`

- **Еволюція секретів:** нуль захардкоджених токенів у коді → у Git лише шаблон `.env.example` → у продакшені та MCP-серверах динамічні короткоживучі облікові дані через **HashiCorp Vault**.
- **Аудит перед найпершим `git add` нового репо:** перевірка на 5 масок — `.env*`, `credentials*`, `*.key`, `*.pem`, `client_secret*.json`.
- **Асиметрична політика `git push`:**
  - **`~/Projects/` (особистий GitHub):** дозволено автокоміт і одразу `git push` у кінці задачі для миттєвої синхронізації між машинами (незавершену роботу — у гілку `wip/<task>`).
  - **`~/Work/` (корпоративний GitLab роботодавця):** локальний коміт дозволено, але **`Bash(git push:*)` завжди у списку `ask`!** Кожен пуш у корпоративний GitLab запускає важкий CI/CD та спалює спільні раннери команди — фінальне підтвердження завжди за людиною.

## 7. Практичне завдання до Серії 03

- 🟢 **Базовий рівень:** Скопіюйте шаблон `settings.security-baseline.json` зі Starter Kit у `.claude/settings.json` свого проєкту та перевірте його через `claude doctor`. Запустіть сесію, перевірте активний `/sandbox` і проведіть краш-тест: переконайтеся, що автотести стартують в Auto Mode без жодних вікон, а спроба прочитати `.env` миттєво блокується.
- 🟡 **Поглиблений рівень:** Пройдіть майстер `/auto-mode-setup` для свого основного репозиторію, налаштуйте мінімальний білий список `sandbox.network.allowedDomains` під свій мовний стек і перевірте роботу прапорців `blockReadsOutsideWorkingDirectories` та `blockWritesOutsideWorkingDirectories`, спробувавши звернутися до файлу за межами проєкту.
- 🔴 **Архітектурний рівень:** Реалізуйте асиметричну політику між `~/Projects/` (автопуш у власні репо та гілки `wip/<task>`) та `~/Work/` (примусовий `ask` на `Bash(git push:*)` у `.claude/settings.local.json`). Клонуйте будь-який відкритий репозиторій із GitHub і проведіть його безпечний аудит за протоколом `ls -la .claude` → `claude --bare --permission-mode plan`.
