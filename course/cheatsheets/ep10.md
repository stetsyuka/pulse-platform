## 1. Headless режим (`-p` / `--print`): еталонні прапорці автоматизації

Ніколи не парсіть сирий текстовий вивід LLM регулярними виразами і не покладайтеся на домашні конфіги розробника у серверних скриптах.

| Прапорець | Призначення у `v2.1.322` | Чому це критично для продакшену |
|---|---|---|
| **`-p` (`--print`)** | Одноразовий неінтерактивний прогін (читає `stdin`, пише `stdout`) | Перетворює агента на стандартний елемент Unix-пайплайна (лог збірки на `stdin`, діагноз на `stdout`) |
| **`--bare`** | Стерильний запуск без домашніх плагінів, автопам'яті, keychain та автопошуку `CLAUDE.md` | **100% відтворюваність** між ноутбуком і CI-сервером + миттєвий холодний старт (читає лише `ANTHROPIC_API_KEY` і явно передані прапорці) |
| **`--permission-prompts none`** | Автоматична відмова на будь-яку дію, яка попросила б підтвердження людини | Гарантує, що нічний cron або CI-джоба **ніколи не зависне** в очікуванні клавіші `Enter` |
| **`--output-format json`** | Повертає єдиний JSON-конверт (`result`, `structured_output`, `session_id`, `total_cost_usd`) | Дозволяє точно логувати вартість кожного виклику та надійно забирати дані через `jq` |
| **`--output-format stream-json`** | Потоковий JSONL у реальному часі (`+ --forward-subagent-text --include-hook-events`) | Жива телеметрія прогресу субагентів і хуків для дашбордів та оркестраторів |
| **`--json-schema '<schema>'`** | Клієнт перевіряє відповідь за схемою; об'єкт — у `.structured_output` | Виключає зламаний JSON або зайві пояснення моделі у маркдаун-блоках |
| **`--max-turns <N>`** / **`--max-budget-usd <X>`** | Ліміт кроків агента та жорстка фінансова стеля в доларах | Захист бюджету від нескінченних циклів на битих логах (`+ --no-session-persistence`) |

## 2. Розклад, 5 робочих поверхонь та мобільне керування

- **`/loop` проти `/schedule`:**
  - **`/loop`** — локальний циклічний черговий **усередині активної сесії** (динамічний темп, переживає оновлення клієнта, окрема статистика у `/usage`).
  - **`/schedule`** *(колишні routines)* — **хмарні регулярні задачі**, що стартують за cron-виразом, API-вебхуком або подією GitHub навіть при вимкненому комп'ютері.
- **Матриця 5 поверхонь під єдиним акаунтом:**
  1. **Terminal CLI (`claude`)** — конвеєри, хуки, скрипти, десятки паралельних `worktree`.
  2. **VS Code / Cursor Extension** — візуальний inline-diff на виділеному фрагменті коду, спільні MCP-конектори з `claude.ai`, автостиснення у простої.
  3. **Claude Desktop (`claude --desktop --continue`)** — перенесення сесії у графічний інтерфейс ОС.
  4. **Slack (`Claude Tag`)** — виклик агента прямо у командному треді з пам'яттю каналу.
  5. **Mobile `Remote Control`** — офіційний багатосесійний сервер віддаленого доступу з телефона:
     ```bash
     # Усередині tmux на робочій станції (до 32 ізольованих мобільних сесій у git worktree!):
     tmux new -s rc 'claude remote-control --spawn=worktree --capacity 16 --name prod-watch'
     ```
     *Агент і команди виконуються на вашій машині, застосунок лише показує сесію; до моделі йде тільки те, що агент прочитав. Комп'ютер має не спати. Автономна альтернатива без ретрансляторів: `Tailscale + SSH + tmux`.*

## 3. П'ять залізних правил броньованого CI/CD (уроки атак 2026 року)

> **Анатомія реальної загрози (промпт-ін'єкція в CI):** Зловмисник вшиває непряму *Prompt Injection* у заголовок/коментар чужого Issue або PR із форка. Якщо CI-агент має широкий `GITHUB_TOKEN` і доступ до `Bash`, модель може вичитати змінні середовища й вислати секрети назовні або запушити код.

1. **Табу на `pull_request_target` для недовірених форків:** ніколи не запускайте ШІ-агента з доступом до секретів базового репозиторію на сирому коді/коментарях зовнішніх контриб'юторів без ручного гейту (`environment` зі схваленням мейнтейнера).
2. **Мінімальні права `GITHUB_TOKEN`:** оголошуйте `permissions: contents: read` на старті. Право `pull-requests: write` відкривайте **лише на окремому фінальному кроці публікації коментаря**, коли процес `claude` вже завершився.
3. **Дієта інструментів:** для рев'ю PR не потрібні `Bash`, `Write` чи `WebFetch`! Використовуйте `--bare --permission-prompts none --tools "Read,Grep,Glob"` (або режим `--restricted`) + `--max-budget-usd 0.50`.
4. **Санітизація метаданих PR:** ніколи не вставляйте `${{ github.event.pull_request.body }}` напряму в bash-рядок (це пряма shell-ін'єкція!). Передавайте лише через `env:` і огортайте тегами недовірених даних.
5. **Людина перед продакшеном (Human-in-the-Loop):** агент діагностує, коментує та готує патч у ізольованому контейнері, але злиття в `main` і деплой завжди підтверджує інженер.

## 4. Приватний `claude self-hosted-runner` та ізоляція маршрутизації моделей

- **Коли потрібен `self-hosted-runner`:** коли хмарні/мобільні сесії та `/schedule` повинні бачити внутрішні бази даних, приватні реєстри образів і сервіси у закритому VPC або домашній лабі (Proxmox / Docker) без відкриття вхідних портів назовні:
  ```bash
  claude self-hosted-runner \
    --environment-secret-file /run/secrets/pool.secret \
    --capacity 4 --drain-wait-sec 60 \
    --remove-session-state \
    --confine-repo-settings enforce \
    --kill-session-after-min 120 --health-port 8080
  ```
  *Увага:* прапорець `--use-anthropic-git-proxy` перед кожною сесією повністю перезаписує `~/.gitconfig` — запускайте раннер **виключно в окремому контейнері або під сервісним користувачем**!
- **Безпечна гібридна маршрутизація моделей (ізоляція профілів):**
  - **Ніколи** не прописуйте сторонні `ANTHROPIC_BASE_URL` у `~/.zshrc` або основний `~/.claude/settings.json`.
  - Для локального `vLLM`, `LiteLLM` чи `OpenRouter` використовуйте **фізично ізольований профіль**:
    ```bash
    # У файлі ~/.claude-alt/settings.json:
    # "ANTHROPIC_BASE_URL": "http://127.0.0.1:8000" (БЕЗ суфікса /v1 у кінці!),
    # "ANTHROPIC_AUTH_TOKEN": "<GATEWAY_TOKEN>", "ANTHROPIC_API_KEY": ""
    alias claude-local='CLAUDE_CONFIG_DIR=$HOME/.claude-alt claude'
    ```
