## 1. Матриця вибору інструмента оркестрації

| Масштаб і характер задачі | Інструмент | Топологія та суть |
|---|---|---|
| **1–8 зв'язних файлів**, єдиний причинно-наслідковий ланцюжок | **Одна сесія (`Plan Mode` / `opusplan`)** | Цілісний контекст без накладних витрат на координацію |
| **Швидка перевірка 1 гіпотези** посеред розмови | **`/subtask <питання>`** | Ізольована підзадача всередині поточного чату; повертає лише стислий висновок |
| **Паралельний ресерч або аудит із 2–4 кутів** (безпека, перф, тести) | **Декларативні субагенти (`.claude/agents/*.md`)** | Топологія **«Зірка»**: кожен субагент читає сирі файли у власній пам'яті й повертає нагору ~250 слів |
| **Довга автономна задача на 10–30 хв**, поки термінал потрібен для іншого | **Фонова сесія (`claude --bg` + `/goal`, або `/fork`)** | Окремий фоновий процес під контролем панелі `claude agents` |
| **Наскрізна фіча на 3–4 шари** (Backend + Frontend + E2E), де треба узгодити живий інтерфейс | **`Agent Teams`** (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`) | **Горизонтальна мережа**: іменовані колеги (`name`) спілкуються напряму один з одним через `SendMessage` |
| **Масова однотипна операція на 15–200+ модулів** (міграція SDK, аудит 120 ендпоінтів) | **Dynamic Workflows (`/effort ultracode`)** | **Програмний `Map-Reduce`**: Claude генерує виконуваний JS-оркестратор із пакетним запуском, ретраями та зведеним звітом |

## 2. Анатомія бойового субагента у `.claude/agents/*.md` (`v2.1.322`)

- Командні агенти (комітяться в Git): `.claude/agents/<name>.md`
- Особисті глобальні агенти користувача: `~/.claude/agents/<name>.md`

```markdown
---
name: codebase-explorer
description: "Fast read-only scout for mapping modules, dependencies, and call sites. Does NOT modify files. Trigger words: map architecture, find usages, де використовується, досліди модуль."
model: haiku
effort: low
maxTurns: 12
omitClaudeMd: true
tools: Read, Glob, Grep
---

Ти — швидкий інженерний розвідник кодової бази (тільки читання).
Поверни концентрований звіт до 250 слів: точки входу, точні шляхи `file:line`, залежності та ризики.
```

**Ключові поля YAML frontmatter:**

- `name` — унікальний ідентифікатор (`kebab-case`).
- `description` — **головний тригер маршрутизації** (Claude читає його на старті, щоб вирішити, коли делегувати задачу).
- `tools` — мінімальний білий список інструментів (без `Edit`/`Write` агент фізично не змінить жодного рядка).
- `model` — `haiku` (`Haiku 5.5`), `sonnet` (`Sonnet 5.5`), `opus` (`Opus 5.5`) або `inherit`.
- `effort` — глибина міркувань (`low` | `medium` | `high` | `xhigh` | `max`).
- `maxTurns` — жорсткий ліміт кроків проти зациклення (рекомендовано `10–15` для розвідників).
- `isolation: "worktree"` — автоматичний запуск субагента у власному ізольованому `git worktree` для безпечного паралельного запису.
- `omitClaudeMd: true` *(новинка `v2.1.271`)* — вимикає завантаження `CLAUDE.md` для вузьких утилітарних субагентів, економлячи тисячі стартових токенів на кожному виклику.

## 3. Командний центр фонових сесій (`claude agents`)

| Команда / Комбінація | Призначення |
|---|---|
| `claude --bg -w feat-x -n "task-x" "<prompt>"` | Запустити іменовану сесію у фоні у власному `git worktree` (повертає короткий `id`) |
| `/fork` *(усередині чату)* | Відбрунькувати копію поточної розмови в нову фонову сесію (позначка `bg` у `/resume`) |
| `claude agents` | Відкрити інтерактивну панель **Agent View** (усі активні та фонові сесії на одному екрані) |
| `claude agents --json --all` | Вивести машинний JSON-список активних і завершених сесій (для скриптів і статус-барів) |
| `claude logs <id\|name>` | Переглянути свіжий термінальний вивід фонової сесії без підключення до неї |
| `claude attach <id\|name>` | Живе підключення до фонової сесії (`←` — назад у Agent View; `Ctrl+Z` — назад у шелл без зупинки!) |
| `/goal <критерій>` | Автономний цикл: ітерувати кроки й перевірки, доки об'єктивна умова готовності не буде виконана |
| `claude stop <id>` *(або `Ctrl+X Ctrl+K` у TUI)* | М'яко зупинити фонову сесію зі збереженням історії (або погасити всі фонові агенти в чаті; `Ctrl+F` у `claude agents` — пошук) |
| `claude rm <id>` | Чисто видалити завершену фонову сесію та її `git worktree` (захищає незапушені коміти!) |
| `claude respawn --all` | Перезапустити фонові сесії на оновленій версії бінарника Claude Code |

## 4. Безпека `Agent Teams` та змінні середовища роїв

**Три правила захисту від колізій файлів у `Agent Teams` (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`):**
1. **Contract-First:** спільний файл `docs/specs/api-contract.md` фіксується до старту в режимі **тільки читання**.
2. **Жорсткі кордони папок:** кожен іменований учасник (`name`) пише виключно у свій каталог (`src/api/**` vs `web/src/**` vs `tests/e2e/**`).
3. **Фізична ізоляція:** при ризику перетину у спільних файлах вмикаємо `git worktree` + хуки `WorktreeCreate` / `WorktreeRemove`.

**Змінні керування бюджетом і масштабом:**

- `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=20` — стеля одночасних паралельних субагентів.
- `CLAUDE_CODE_SUBAGENT_EFFORT=low|medium|high` *(новинка `v2.1.316`)* — глобальний контроль зусиль субагентів.
- `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=sonnet` — примусове обмеження моделі субагентів.
- `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=sonnet|haiku` *(новинка `v2.1.296`)* — модель масових воркерів у віялі `/effort ultracode`.

## 5. Еталон «Трирівневий Workspace Hub + Model Routing»

- **Рівень 1 — Global Hub (`workspace-hub/`):** єдина точка входу `CLAUDE.md` (карта репозиторіїв і граф міжпроєктних залежностей), глобальні `.claude/rules/`, спільна бібліотека `.claude/skills/shared/` (0 дублів!) та 3 глобальні агенти: `router`, `knowledge`, `reviewer`.
- **Рівень 2 — Доменні контури (`cloud-enterprise-env/`, `platform-lab-env/`):** локальні правила оточень (`PROD/QA`) та вузькі інженерні субагенти під конкретний стек.
- **Model Routing за ціною помилки:**
  - **Opus 5.5 (`\$4` / `\$20` за 1M)** → архітектура, граф зв'язків (`knowledge`), крос-рев'ю (`reviewer`), аудит безпеки (`security-reviewer`), генерація JS-оркестратора в `ultracode`.
  - **Sonnet 5.5 (`\$2` / `\$10` за 1M)** → 75–80% доменних агентів-виконавців (`implementer`, CI/CD, Terraform, Grafana, фронтенд/бекенд).
  - **Haiku 5.5 (`\$0.10` / `\$0.50` за 1M) + `omitClaudeMd: true`** → миттєві пошукові скаути (`codebase-explorer`) та масові однотипні перевірки.

## 7. Практичне завдання до Серії 09

- 🟢 **Базовий рівень:** Створіть у своєму проєкті `.claude/agents/codebase-explorer.md` (`model: haiku`, `omitClaudeMd: true`, тільки читання) та `.claude/agents/security-reviewer.md` (`model: opus`, `effort: high`, тільки читання) на базі шаблонів зі Starter Kit. Запустіть їх паралельно для аналізу ключового модуля й перевірте через `/status` або `/cost`, наскільки чистим лишилося головне вікно чату.
- 🟡 **Поглиблений рівень:** Запустіть ізольовану фонову сесію командою `claude --bg -w feat-audit -n "audit"`, підключіться до неї через `claude attach audit`, задайте об'єктивний критерій готовності через `/goal` (наприклад, зелені тести та лінтер), від'єднайтеся в шелл комбінацією `Ctrl+Z`, перевірте потік через `claude logs audit` та панель `claude agents`, а після завершення чисто приберіть сесію й робоче дерево через `claude rm <id>` (stop і rm приймають id, не імʼя).
- 🔴 **Архітектурний рівень:** Спроєктуйте трирівневий **Workspace Hub** для своїх робочих та особистих проєктів (винесіть спільні навички у `shared/`, опишіть агентів `router`, `knowledge`, `reviewer` та складіть таблицю **Model Routing** між `Opus 5.5`, `Sonnet 5.5` і `Haiku 5.5`). На багатомодульному репозиторії виконайте пакетний аудит або міграцію через **`/effort ultracode`** і проконтролюйте виконання у `/workflows`.
