## 1. Два закони уваги: чому модель ігнорує роздутий `CLAUDE.md`

1. **Міф про «ремарку релевантності»:** у старих гайдах пишуть, що Claude Code загортає `CLAUDE.md` у ремарку «може бути нерелевантним». У поточній версії (перевірено на живій сесії, 2.1.31x) обгортка каже протилежне: інструкції проєкту **переважають поведінку за замовчуванням і виконуються точно**. Ігнорування — наслідок самого файлу: модель мусить вибирати, що стосується задачі, і критичні правила тонуть у «воді». Claude Code попереджає про завеликі файли інструкцій на старті, а `/doctor` пропонує викинути те, що видно з коду.
2. **Стеля інструкцій (емпіричний орієнтир практиків ~150–200 правил, не офіційна межа):** Навіть при вікні 1 000 000 токенів модель стабільно виконує обмежену кількість поведінкових правил. Частину вже займає системний промпт Claude Code — тож на всі рівні конфігурації лишається **приблизно сотня**. Перевищення ліміту знижує слухняність по **всіх** правилах одночасно.

> **Золотий фільтр кожного рядка:** *«Якщо я видалю цей рядок просто зараз, чи почне Claude помилятися на моєму проєкті?»* Якщо ні — безжально видаляйте.

## 2. Що писати і чого категорично НЕ писати в `CLAUDE.md`

| ✅ Обов'язково включати | ❌ Категорично виключати |
|---|---|
| Точні команди збірки, лінтерів і запуску **одного** тесту (`pytest -k`) | Те, що агент за секунду виведе з `package.json` / `pyproject.toml` |
| Нестандартні інваріанти проєкту (напр., гроші тільки в центах `int`) | Загальні лекції про PEP8, SOLID та «пиши чистий код без багів» |
| Дієві маршрути до реальних файлів-зразків (`routers/orders.py`) | Довгі приклади коду на кілька екранів або копії документації API |
| Правила позитивної заміни: *«Замість X використовуй Y»* | Голі заборони без вказівки дозволеного інструмента-замінника |
| Реальні підводні камені середовища (перевірені інцидентами) | Пофайловий перелік директорій (інструмент `Glob` бачить це сам) |
| Короткий критерій готовності задачі та правила Git-гілок | Правила для вузьких папок (→ у `rules/`) та критичну безпеку (→ у `Hooks`) |

## 3. Анатомія еталонного `CLAUDE.md` (орієнтир: 80–120 рядків)

1. **Суть і межі системи** (3–4 рядки: призначення продукту, ключовий стек і головні директорії).
2. **Команди перевірки та налагодження** (точковий тест, лінтер, типізація, де лежать локальні логи й тестова БД).
3. **Карта архітектури та файли-зразки** (формулюємо як інструкцію дії: *«Перед створенням X прочитай зразок Y»*).
4. **Інваріанти, підводні камені й альтернативи** (бізнес-обмеження та перевірені граблі проєкту).
5. **Робочий цикл Git і критерій завершення** (формат гілок/комітів + обов'язковий зелений статус перевірок).

**Інструменти розвитку файлу:**
- `/init` — генерує стартовий чорновик (обов'язково приберіть вручну більшу частину очевидного тексту).
- `# <правило>` — швидке додавання нотатки в інструкції прямо під час сесії.
- `@docs/git-workflow.md` — модульний імпорт зовнішнього файлу (підтримує до 5 рівнів вкладеності).

## 4. Багатошарова ієрархія пам'яті та субагенти

| Рівень (згори донизу) | Розташування | Коли завантажується | Призначення |
|---|---|---|---|
| **1. Managed Policy** | Системна папка ОС компанії | Завжди на старті | Незмінні корпоративні стандарти безпеки |
| **2. Глобальний User** | `~/.claude/CLAUDE.md` | Завжди у кожній сесії | Ваша інженерна дисципліна на всіх проєктах (під `chezmoi`) |
| **3. Кореневий Project** | `./CLAUDE.md` (або `.claude/CLAUDE.md`) | Завжди для цього репо | Командний паспорт проєкту в Git |
| **4. Вкладений Subdir** | `services/api/CLAUDE.md`, `apps/web/CLAUDE.md` | **Ліниво (on-demand!)** | Підтягується тільки коли агент торкається файлів підпапки |
| **5. Локальний Private** | `./CLAUDE.local.md` (у `.gitignore`) | Завжди для вас локально | Приватні порти стендів, локальні URL, чернетки спринту |

- **`Auto-memory` (`/memory`)**: особистий блокнот самого агента (`MEMORY.md` + тематичні файли з `modified` timestamp). Не дублюйте з `CLAUDE.md`; цінні командні знахідки переносьте у `CLAUDE.md`.
- **`omitClaudeMd: true` *(новинка осені 2026, `v2.1.271`)*:** додавайте у YAML-шапку легких пошукових субагентів (`.claude/agents/*.md`), щоб не навантажувати їх проєктними правилами й економити тисячі токенів.
- **`.claudeignore`**: закривайте дампи `*.sql`, `*.csv`, `dist/`, `.next/`, щоб пошук не затягував гігабайти сміття.

## 5. Модульні правила `.claude/rules/*.md` та матриця вибору

У Claude Code фільтрація правил за масками файлів задається у YAML frontmatter ключем **`paths:`** *(не плутайте з `globs:` із редактора Cursor!)*.

```markdown
---
paths:
  - "services/api/migrations/**/*.py"
  - "**/*.sql"
---
# Правила міграцій БД
- Кожна міграція Alembic мусить мати зворотний метод `downgrade()`.
- Заборонено додавати `NOT NULL` без безпечного `server_default` на живих таблицях.
```

| Яка перед вами вимога? | Куди класти? |
|---|---|
| Потрібна майже в кожній задачі проєкту | Кореневий `CLAUDE.md` (або хаб `AGENTS.md`) |
| Стосується лише окремого сервісу, папки чи типу файлів | `.claude/rules/*.md` із фільтром `paths:` |
| Довгий покроковий воркфлоу / інструкція на 1–2 сторінки | Навичка `.claude/skills/<name>/SKILL.md` |
| Критична заборона, яку LLM не має права порушити ніколи | Детермінований `Hook` (`PreToolUse`, код виходу `2`) |

## 6. Крос-агентний хаб `AGENTS.md` та синхронізація `chezmoi`

- **Мультиінструментальні команди (`v2.1.277+`):** тримайте єдиний канонічний паспорт і таблицю скілів (`.claude/skills/*/SKILL.md`) у кореневому **`AGENTS.md`**. Якщо потрібні `CLAUDE.md`, `.cursor/rules` чи `.github/copilot-instructions.md` — робіть їх тонкими 3-рядковими редірект-стабами (`@AGENTS.md`) без жодного дублювання тексту.
- **Синхронізація між macOS, Linux та WSL:** зберігайте `~/.claude/CLAUDE.md` у своєму єдиному репозиторії `dotfiles` під керуванням **`chezmoi`** (`dot_claude/CLAUDE.md`):
  - Зберегти правку: `chezmoi re-add ~/.claude/CLAUDE.md` → `git commit && git push`
  - Оновити на іншій машині: `chezmoi update`

## 7. Діагностика промптів 2026 та оперативна гігієна живої сесії

| Команда | Призначення |
|---|---|
| `/doctor prompt-audit` | Ревізія `CLAUDE.md`, `rules`, `skills` та агентів на суперечності, «воду» й застарілі патерни старих моделей |
| `/btw <питання>` | Побічна довідка посеред роботи, яка **не записується** в історію діалогу і не розмиває контекст |
| `/compact <фокус>` | Кероване стиснення історії на стику етапів зі збереженням вказаних артефактів |
| `/clear` | Повне очищення контексту між непов'язаними задачами (або після **2 невдалих спроб** поспіль!) |
| `/memory` | Миттєвий огляд усіх завантажених шарів `CLAUDE.md`, активних `rules` та нотаток `Auto-memory` |

- 🟡 **Поглиблений рівень:** Винесіть специфічні правила окремих шарів із кореневого `CLAUDE.md` у мінімум 2 файли `.claude/rules/*.md` із точними масками `paths:`, створіть `.claudeignore` для важких файлів і перевірте ліниве підвантаження через `/memory`.
- 🔴 **Архітектурний рівень:** Побудуйте у командному репозиторії зв'язку «Канонічний хаб `AGENTS.md` + тонкий стаб `CLAUDE.md`», а свій глобальний `~/.claude/CLAUDE.md` підключіть до репозиторію `dotfiles` через `chezmoi` (`dot_claude/CLAUDE.md`) і перевірте цикл оновлення.
