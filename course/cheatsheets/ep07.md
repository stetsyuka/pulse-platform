## 1. Еволюція від `.claude/commands/` до трирівневого Progressive Disclosure у `Skills`

Старі одиночні файли `.claude/commands/*.md` працюють у режимі зворотної сумісності, але стандартом 2026 року є модульні навички **`.claude/skills/<name>/SKILL.md`** (відкритий крос-агентний стандарт Agent Skills, інтегрований із таблицею-індексом у кореневому `AGENTS.md`).

| Рівень розкриття | Що завантажується у вікно 1M | Вартість у токенах | Коли спрацьовує |
|---|---|---|---|
| **1. Метадані (Discovery)** | Лише `name` + `description` із YAML-шапки | **~40–60 токенів** на скіл (загальний бюджет описів — 2% вікна контексту) | Завжди на старті сесії |
| **2. Тіло навички (Activation)** | Повний текст `SKILL.md` (орієнтир: **90–250 рядків**, суворо ≤500) | **~800–2 000 токенів** | Тільки при виклику `/name` або семантичному збігу задачі |
| **3. Ресурси (`references/`, `scripts/`)** | Довідники читаються точково; **код скриптів у `scripts/` взагалі не входить у контекст** (лише `stdout`) | **Майже 0 токенів** на код утиліти | Лише на конкретному кроці процедури |

**Пріоритет розташування скілів:** `1. Enterprise Managed` → `2. Personal (~/.claude/skills/)` → `3. Project (.claude/skills/)` → `4. Plugin (<plugin>/skills/)`.

- Гаряче оновлення без перезапуску: **`/reload-skills`** та **`/reload-plugins`**.
- **Правило ревізії конфіг-папок:** деякі ШІ-інструменти створюють власні машиночитані списки скілів без розширення файлу — перевіряйте конфіг-папки прямим `ls -la` (не покладайтеся лише на `**/*.json`), документуйте їх у `AGENTS.md` і не перейменовуйте вручну.

## 2. Анатомія бездоганного `SKILL.md`: YAML Frontmatter та динамічні змінні

> **Золотий закон автоактивації:** пишіть `description` як семантичний радар із 3 елементів: **(1) Що робить**, **(2) Коли викликати + тригерні слова користувача**, **(3) Чим відрізняється від сусідньої навички** (`db-migration` проти `db-rollback`).

| Поле YAML frontmatter | Приклад значення | Інженерне призначення |
|---|---|---|
| `name` | `db-migration` | Має літера в літеру збігатися з назвою папки (`kebab-case`) |
| `description` | `Створює zero-downtime міграції...` | Головний радар вибору скіла моделлю |
| `argument-hint` | `"[revision_name] [service]"` | Підказка аргументів у меню автодоповнення `/` |
| `disable-model-invocation` | `true` | Забороняє моделі запускати скіл самій — **тільки ручний виклик людиною** (деплой, відкат) |
| `user-invocable` | `false` | Ховає скіл із меню `/`, залишаючи його як фонові знання для самого агента |
| `allowed-tools` | `Read, Grep, Glob, Bash(alembic *)` | Обмеження дозволених інструментів під час виконання навички |
| `context` | `fork` *(+ опційно `background: false`)* | Запускає важкий скіл в **ізольованому вікні субагента** (з `v2.1.218+` фоново за замовчуванням), повертаючи лише чисте резюме |
| `agent` | `Explore` | Тип субагента при роботі з `context: fork` |
| `model` / `effort` | `opus` / `high` *(або `haiku` / `low`)* | Примусовий вибір моделі та глибини мислення для цієї навички |

**Динамічна підстановка в тілі `SKILL.md`:**

- `$ARGUMENTS` — увесь рядок аргументів; `$ARGUMENTS[0]`, `$ARGUMENTS[1]` — позиційні аргументи.
- `${CLAUDE_SESSION_ID}` — поточний ID сесії; `${CLAUDE_SKILL_DIR}` — абсолютний шлях до папки скіла (для виклику `${CLAUDE_SKILL_DIR}/scripts/check.py`).
- `` !`alembic current` `` або `` !`git diff --stat HEAD` `` — **динамічна шелл-ін'єкція**: виконується локально *до* відправки промпта моделі й підставляє живий вивід прямо в інструкцію.
- **Семиблоковий каркас тіла:** `1. Заголовок` → `2. Роль і сусідні скіли` → `3. Посилання на архітектурний док` → `4. Таблиця "Крок 0: збір фактів" (Питай, а не вгадуй!)` → `5. Нумеровані кроки` → `6. Перевірені реальними інцидентами граблі` → `7. Команда верифікації`.

## 3. Маркетплейси та командні `Plugins`

Забудьте вигадані команди зі старих статей на кшталт встановлення скілів через звичайний `npm install @anthropic/skill-deploy`. Реальний синтаксис 2026 року:

```bash
# Підключення офіційного або корпоративного Git-каталогу в сесії
/plugin marketplace add anthropics/skills
/plugin marketplace add acme-org/engineering-plugins

# Встановлення версіонованого плагіна з конкретного маркетплейса
/plugin install document-skills@anthropic-agent-skills
/plugin install backend-standards@acme-engineering

# Генерація каркасу власного плагіна за 10 секунд (v2.1.157+)
claude plugin init backend-standards --with skills agents hooks mcp

# Керування та конфігурація з CLI
claude plugin list
claude plugin configure backend-standards      # Налаштування опцій плагіна (v2.1.285+)
claude plugin disable <name> && claude plugin prune
```

- **Корпоративний білий список у `settings.json` (`v2.1.232+`):** використовуйте `additionalMarketplaces` та `allowedMarketplaces`.
- **Хмарна синхронізація з `claude.ai` (`v2.1.275+`):** увімкнені у вебі скіли й плагіни синхронізуються в термінал автоматично (вимикається на серверах через `syncClaudeAiSkills: false` та `syncClaudeAiPlugins: false`).
- **Маніфест `.claude-plugin/plugin.json`** об'єднує в один пакет `skills/`, `agents/`, `hooks/hooks.json` (використовуйте `${CLAUDE_PLUGIN_ROOT}` для кросплатформних шляхів) та `.mcp.json`.

## 4. Ревізія вартості та регресійне тестування (`claude plugin eval`)

| Інструмент | Коли запускати | Що перевіряє |
|---|---|---|
| **`/skill-doctor`** *(v2.1.261+; у 2.1.322 — вкладка Stats у `/plugin`)* | Раз на 2 тижні або після додавання нових скілів | Вартість кожного скіла в контексті, скільки разів він викликався і коли востаннє — мертвий баласт видно одразу |
| **`claude plugin details <name>`** | Перед увімкненням плагіна на команду | Повна інвентаризація компонентів (скіли, агенти, хуки, MCP) і прогнозований податок у токенах на сесію |
| **`claude plugin eval`** *(v2.1.269+)* | У локальній розробці скілів та в CI/CD на кожен PR | Проганяє тестові сценарії (`evals/**/case.yaml` або `prompt.md + graders/*.md`), порівнює з базовою лінією без плагіна (`no-plugin baseline`) і повертає точний бал `0.00..1.00` |

```bash
# Створити шаблон автотесту для навички/плагіна
claude plugin eval init --bare safe-migration

# Прогін навички з контрольною групою без неї (у серії: Haiku, 1.00 проти 0.88, $0.02)
claude plugin eval .claude/skills/db-migration \
  --runs 3 \
  --model haiku \
  --threshold 0.9 \
  --max-cost-usd 1.50 \
  --no-publish \
  --allow-tools Write Edit \
  --json eval-report.json
# Код виходу: 1 — бал нижче порогу, 2 — вичерпано --max-cost-usd
```

Кейс `evals/index-on-live-table/case.yaml` (схема `1.0`; типи грейдерів: `regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`):

```yaml
schema_version: "1.0"
name: index-on-live-table
execution:
  prompt: |
    Жива таблиця orders має мільйони рядків; потрібен індекс по status.
    Створи services/api/migrations/versions/0003_orders_status_index.py.
  max_turns: 15
  allowed_tools: [Read, Glob, Grep, Write, Edit, Skill]
runs: 3
graders:
  - {type: tool_used, name: skill-fired, tool: Skill, input_match: db-migration}
  - {type: file_exists, name: migration-written, path: services/api/migrations/versions/0003_orders_status_index.py}
  - type: regex
    name: concurrent-index
    target: {source: file, path: services/api/migrations/versions/0003_orders_status_index.py}
    pattern: postgresql_concurrently\s*=\s*True|CREATE\s+INDEX\s+CONCURRENTLY
    flags: i
  - {type: llm, name: explains-why, criteria: "Пояснює, чому індекс конкурентний, і downgrade не порожній"}
```

Робоча тека прогону порожня (без `--scaffold`), тож кейс має бути самодостатнім. Оцінюйте результат, а не форму: `tool_used: Skill` під контрольною групою лише індикатор і в бал не входить.

## 5. Архітектура `Claude Mods` (`v2.1.287+`) та бойовий кейс `context-bar`

**Claude Mod** — це типізований модуль на TypeScript/TSX (`hooks/hooks.json` → `{"modules": ["./register.tsx"]}`), який працює безпосередньо поверх клієнтського рушія пакету `'claude-code'` на поверхнях `terminal` і `desktop`.

| Подія Mod SDK (`claude-code`) | Призначення | Приклад дії |
|---|---|---|
| **`ui.render`** (`AbovePrompt`, `Pane`, `PromptHint`, `TurnDuration`) | Малювання реактивних компонентів `Box` і `Text` *(у `v2.1.299+` використовуйте `weight="bold"` замість застарілого `bold`)* | Жива шкала контексту `context-bar` над рядком вводу |
| **`tool.check`** | Програмний дозвіл або блокування до запуску інструмента *(завжди страхуйте через `.catch(() => ({ decision: "deny" }))`)* | Заборона деплою в п'ятницю ввечері або поза релізною гілкою |
| **`skill.prompt`** / **`prompt.mention`** | Збагачення тексту скіла на льоту / блокування небезпечних `@`-згадок ще до читання диска | Автододавання версії схеми БД у скіл; відмова на `@.env` |
| **`session.start` / `turn.complete` / `session.compact`** | Життєвий цикл сесії + локальний замір `await $.session.usage({ breakdown: 'summary' })` | Миттєве оновлення шкали пам'яті без жодного мережевого запиту |

## 6. Практичне завдання до Серії 07

- 🟢 **Базовий рівень:** Перетворіть одну регулярну інженерну процедуру свого проєкту (міграція БД, створення API-роута або релізний чекліст) на модульний `.claude/skills/<name>/SKILL.md` обсягом 80–120 рядків за 7-блоковим стандартом. Пропишіть точний `description` із тригерами та відмежуванням від сусідніх дій, додайте `argument-hint`, `$ARGUMENTS` і динамічну ін'єкцію `` !`git status -sb` ``, підвантажте через `/reload-skills` і перевірте у `/skill-doctor`.
- 🟡 **Поглиблений рівень:** Згенеруйте командний плагін через `claude plugin init`, додайте до нього аудиторську або міграційну навичку з `context: fork` та детермінованим скриптом у `scripts/`, створіть тестовий кейс через `claude plugin eval init --bare` і досягніть стабільного проходження `claude plugin eval` із порогом `--threshold 0.9`.
- 🔴 **Архітектурний рівень:** Розгорніть шаблон мода `context-bar` із папки `starter-kit/ep07/`, підключіть його локально через `claude --plugin-dir`, виведіть у рядок легенди вартість сесії `cost.usd` та кольоровий індикатор зони *Context Rot* (`OPTIMAL <25%` / `WARN 25–50%` / `COMPACT NOW >50%`) і проженіть автотест UI на `claude-code/testing` для поверхонь `terminal` та `desktop` командою `claude plugin test ./context-bar`.
