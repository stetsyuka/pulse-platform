# Специфічне для Claude Code

## Як працюємо в цьому репо
- Велика задача (3+ файли або нова таблиця) — спершу план у Plan Mode, потім реалізація.
- Перед зміною схеми БД прочитай `docs/architecture/db-conventions.md` і онови міграцію в тому ж коміті.
- Тести пишемо до реалізації; файли в `services/api/tests/` під час реалізації не змінюємо без прямого дозволу.
- Модульні правила для бекенду підвантажуються з `.claude/rules/` за масками шляхів.

## Підводні камені, на яких уже спотикались
- Async SQLAlchemy: ледаче довантаження зв'язків дає `MissingGreenlet` — використовуй `selectinload()`.
- У тестах БД — SQLite в пам'яті (`tests/conftest.py`); SQL, специфічний для PostgreSQL, обгортай вибором діалекту.
- `logs/` — приклади логів для розбору, не редагуй їх.

## Git
- Гілки `feat/<slug>`, `fix/<slug>`, незавершене — `wip/<task>`.
- Conventional Commits; у тілі коміту — «чому», а не «що».

## Хуки (Серія 06)
- `.claude/hooks/` — хуки проєкту: щит від секретів і руйнівних команд, автоформатування, аудит команд.
- На `Stop` хук запускає `make check`; червоне — виправляй код, а не тести.
