# ADR 004: черга вихідних вебхуків — outbox-таблиця в PostgreSQL

- **Статус:** прийнято (Серія 04)
- **Контекст:** партнерам треба надійно повідомляти про зміну статусу замовлення. Подія не має губитися, якщо API впав одразу після коміту, і не має доставлятися як «нова» вдруге.

| Варіант | За | Проти |
|---|---|---|
| Outbox-таблиця в PostgreSQL | подія пишеться в тій самій транзакції, що й зміна замовлення; нічого нового в інфраструктурі | воркер опитує таблицю; на десятках тисяч подій за хвилину знадобиться партиціювання |
| Redis Streams | швидко, є consumer groups | друга система зі своєю надійністю; запис у БД і в Redis не атомарний — можлива втрата події |
| Окремий брокер (RabbitMQ, Kafka) | масштаб, маршрутизація | непропорційна складність для поточного навантаження |

- **Рішення:** outbox-таблиця `webhook_deliveries` з `UNIQUE (idempotency_key)`. Перехід на брокер — коли опитування стане вузьким місцем (метрика: вік найстарішої `pending`-доставки > 60 с).
